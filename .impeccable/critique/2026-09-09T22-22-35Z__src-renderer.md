## Design Specificity Verdict

**LLM assessment: mostly category-interchangeable.** An unrelated "AI dev team" product could adopt this UI tomorrow with only copy changes — the skeleton (left chat sidebar, tabbed main panel, banner stack, composer, status bar) is the standard Cursor/Claude-desktop hybrid in Inter. Genuinely product-specific: the Plan/Build/Danger mode language with dedicated per-theme token triads, the Blueprint 7-phase pipeline surface (the one screen no generic chat tool has), Grill's adversarial identity, and the gold/teal Code Atelier skin. The "atelier" concept stops at token names: Cormorant Garamond ships as 6 woff2 files and is used in exactly 3 inline styles; each tool grabs a different Tailwind hue (Design purple, Health green, Council indigo, Ideas amber, Jira blue), diluting the one brand accent. Four themes exist, but theming is recoloring, not identity.

**Deterministic scan:** 27 findings across 7 rules; 13 survived verification. The detector and the LLM review converged independently on the two biggest identity findings: `side-tab` (11 fired / 6 confirmed — the classic AI-UI accent-bar tell, spread across three unrelated feature areas = a house pattern, not one-offs) and `overused-font` (2/2 confirmed — Inter as body font, while the distinctive display face sits bundled and unused). ## Overall Impression

An unusually disciplined app with a wayfinding problem and a theme debt. The craft is real — state feedback, safety architecture, and the reading surface are better than most shipped products — but the flagship workflows hide inside a settings panel, and a ~9% raw-color leakage plus three dead token classes quietly break the light theme and several components. The single biggest opportunity: re-center the app on its one unmatched surface (Blueprint runs) and spend the brand budget (the unused display font, the gold accent) there.

## What's Working

1. **State photography.** Streaming pulse on sidebar avatars, per-phase durations, stall detection with a human sentence, completion flash, orphaned-run resume — in an app of autonomous background agents, "what is happening and did it finish?" is answered continuously (`ChatItem.tsx:83-109`, `ChatPanel.tsx:279-303`, `layout/StatusBar.tsx`).
2. **Safety architecture.** Branch-by-default chats, preflight blockers separating blockers from warnings, clarify gates, decorrelation warning, design-command conflicts disabled *with the blocker named* — each guard is specific and placed at the moment of risk.
3. **Motion + focus discipline.** Duration/easing tokens, global `prefers-reduced-motion` kill with JS-level respect in canvas scenes, universal `:focus-visible` double-ring, a model div-button implementation (`ChatItem.tsx:206-226`), and a documented a11y rebuild of the Switch. Chat rendering is virtualized with memoized bubbles.

## Priority Issues

1. **[P1] Contrast failures at scale, worst in porcelain (light) theme.** `text-muted` = 2.45:1 on porcelain (1,451 usages) and fails in glass/developer too; `text-white` on accent buttons fails in all three dark themes (96 usages, incl. every ConfirmDialog destructive button); ~788 raw palette classes (`text-amber-400` ≈ 1.6:1 on porcelain) wash out the light theme; charts are entirely theme-blind. Fix: an `--color-on-accent` token per theme (the correct `.btn-primary` pattern already exists at `main.css:203`), re-tune muted/secondary per theme, route status colors through semantic tokens. → `/impeccable colorize`
2. **[P1] Dead token classes render elements with no background.** `bg-surface-elevated`, `bg-surface-panel`, `bg-success-hover` reference tokens defined in no theme: every Toast renders transparent (`Toast.tsx:43`), two modal cards have no background, ~30 hover states silently don't exist. Fix: define or sweep-replace the tokens; add a CI lint for undefined `--color-*` references. → `/impeccable harden`
3. **[P1] Primary workflows buried inside "Workspace Settings".** 14 visible nav destinations; the sidebar opens Settings-first; Blueprints (the flagship) lives three levels deep; grill conversations vanish from the chat list and their notifications route to "ideas". Simultaneously a wayfinding, recall, and cognitive-load failure. Fix: rename the nav to "Workspace", split tools into ≤7-item groups, first-class Blueprints entry, grill sessions visible with a badge. → `/impeccable shape`
4. **[P2] Keyboard and modal a11y gaps.** No focus trap in any `aria-modal` dialog (Tab escapes behind the modal, WCAG 2.4.3); conversation rename/delete unreachable by keyboard (`hidden group-hover:flex`); message footer actions focusable but invisible when focused; no `lang` on `<html>` (WCAG A); 0/30 textareas labelled (wizard brief input is placeholder-only); CheckpointApprovalModal — the highest-stakes dialog — has no Esc, trap, or initial focus. → `/impeccable harden`
5. **[P2] Danger mode is one accidental cycle away.** `⌘.` cycles plan→build→danger with no confirmation; only warning is placeholder text. Related: ConfirmDialog auto-focuses the *destructive* button. Fix: confirmation (or hold) to enter Danger; focus Cancel in danger dialogs. → `/impeccable harden`

## Persona Red Flags

**Alex (power user):** ⌘N lands on a form demanding a Title before anything else — every rival lets him type the message first; "Undo to here" is hover-only, forcing the mouse; no command palette for a 14-tab nav; sidebar opens Settings-first so his chat list is one click away every session.

**Sam (accessibility-dependent):** rename/delete unreachable by keyboard; focusable-but-invisible footer actions; two app-blocking modals with no Esc/trap/initial focus; 9–10px text in 405+ places, often muted; on porcelain the raw amber/cyan status colors are near-invisible (≤2:1).

**Riley (stress tester):** renaming a conversation to "New Conversation" then deleting it fires no confirmation (title check treats it as disposable — instant `closeConversation`); a blueprint that fails to start shows its error banner only on the *landing* view, so the active view just stops; "Save to memory" with a broken backend silently reverts (error → console only).

## Questions to Consider

1. If Blueprints is the flagship, why does it live three levels deep under "Settings"? What would the app look like re-centered on *runs* (blueprint/audit/grill sessions) instead of conversations — would the 14-tab nav collapse to ≤5 destinations?
2. The mode system is the core safety metaphor — so why is Danger one click past Build on a cycle pill? What if mode transitions were a small consequential contract ("Build can write files; here's the branch")?
3. Four themes ship, but ~1,047 raw colors and 3 dead tokens bypass the system — is theming a product promise or maintenance debt? Would deleting two themes and linting the token layer produce a more distinctive product than four recolors of an Inter-everything UI?
4. Grill, Council, Health, and Design Audit are all "adversarial review of a thing" — could they merge into one review surface with different panels, ending the hidden-session problem?
